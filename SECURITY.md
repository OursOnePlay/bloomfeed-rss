# Security

Use the latest version of the main branch. Older releases do not have a separate security maintenance schedule.

Do not post credentials, private article content, or exploit details in a public issue.

On GitHub, use the repository's private vulnerability reporting feature if enabled. Otherwise, contact the repository owner privately before disclosing technical details. If neither route is available, open an issue asking for a private reporting channel without including the vulnerability itself.

Include the affected version, a reproduction using test data, the expected behavior, and the impact. Never test against another person's instance without permission.
